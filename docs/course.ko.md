# 해양 자율운항 실습 — 강의계획서와 학생 교재

[English](course.md) · [정확한 채점 식](scoring.md) · [템플릿 사용법](../README.ko.md)

**플랫폼:** WWW-POSIM, ROS 2 Lyrical, Gazebo Jetty, 선택적 ArduPilot. **대상:** 기본 Python 프로그래밍이 가능한 학부·대학원생. **진행:** 12주, 주당 이론 2시간·실습 2시간, 1~3명 팀. 수상 또는 수중 한 부문을 선택해 수강할 수 있으며 두 부문 참가도 가능합니다. RobotX·VRX·RoboSub 등의 실제 과제 유형을 참고한 교육용 대회이며 공식 대회의 예선·동일 규칙은 아닙니다.

## 학습 목표와 AI 사용

학생은 센서 피드백을 이용해 ROS 제어기를 작성하고, 세계 ENU 좌표와 기체 좌표를 구분하며, 시뮬레이션 시간과 실제 사용 시간을 설명할 수 있어야 합니다. 센서 메시지·QoS·주기를 확인하고, 충돌 여유 거리를 반영해 경로를 계획하며, 오래된 데이터·연결 끊김·긴급 중지에 대응해야 합니다. 기본 Autopilot과 직접 작성한 제어기를 같은 조건에서 비교하고, 여러 코스의 기록과 소스·파라미터 버전으로 결과를 재현하는 것이 최종 목표입니다.

AI 코딩·디버깅·문서 작성을 허용합니다. 단, 사용 기록, 알고리즘 흐름 설명, 실패 사례와 수정 근거, 재현 명령을 제출합니다. 생성된 코드를 그대로 제출해도 이해·검증 책임은 팀에 있습니다. API 문법을 어렵게 만드는 대신 정밀도·파도·코스 변화·안전·반복 검증으로 높은 점수를 어렵게 만듭니다. 시각 효과를 실제 센서·물리 검증과 혼동하지 마세요.

## 시스템 구조

브라우저에서 위도·경도·기체·월드를 선택하면 해저·육지 지형으로 충돌 메시를 생성합니다. 각 서버 슬롯은 독립 Gazebo·ROS·브리지·선택적 SITL을 실행합니다. 브라우저는 네이티브 위치와 파도 높이 표본으로 장면을 표시합니다. **ROS2 직접 제어 모드에는 ArduPilot이 실행되지 않습니다.** 학생 코드는 센서 데이터를 받아 추진 명령을 내립니다. Autopilot 모드에서는 MAVROS·ArduPilot이 제어하므로 두 제어권을 함께 실행하지 않습니다.

센서는 읽기 전용 `/ros` WebSocket으로, 허용된 추진 명령은 인증된 `/control` WebSocket으로 전달합니다. 학생 컴퓨터의 릴레이가 센서를 로컬 ROS 토픽으로 다시 발행하고, 학생 노드가 발행한 명령을 서버로 보냅니다. 공개 DDS 멀티캐스트·학생별 서버 셸·임의 서비스 호출은 제공하지 않습니다. 인터넷 배포에서는 HTTPS/WSS만으로 연결할 수 있고 SSH 터널은 선택 사항입니다.

서버는 현재 세션 식별자·독점 제어권·증가하는 명령 순서·속도/힘 제한을 확인합니다. 0.75초 **실제 시간** 동안 새 명령이 없으면 추진력을 0으로 합니다. 시뮬레이션을 멈춰도 통신 장애 검사는 멈추면 안 되므로 watchdog은 실제 시간을 사용합니다. 추진력 0은 위치 고정과 다릅니다. 관성·파도 때문에 움직일 수 있습니다. 브라우저 Stop 이후에는 Enable을 눌러야 재제어할 수 있습니다.

## 설치

### 이메일 계정과 사용 시간

이메일을 로그인 ID로 가입하고 12자 이상 비밀번호를 사용합니다. 계정 메뉴에서 인증 코드를 발송하고 입력하세요. 실제 이메일 발송에는 운영자의 SMTP 설정이 필요합니다. 설정되지 않은 개발 환경은 이를 오류로 안내하며 관리자가 주소를 확인해 인증할 수 있습니다. 사용자가 대학 이메일 도메인을 적었다는 이유만으로 인증·무제한 권한을 부여하지 않습니다.

기본 제한은 설치형 **하루 3시간**, 웹 **하루 1시간**이며 UTC 0시에 초기화됩니다. 웹은 초기 이용 대상 5명, 동시에 독립 시뮬레이션 2개입니다. 빈 슬롯이 없으면 현재 종료 예정 시간을 보여줍니다. 대기열 참여, 나중에 재접속, 설치형 연습 중 선택하세요. 조기 종료·시작 준비·정리 시간 때문에 예상 대기 시간은 변할 수 있습니다. 대기 시간은 실행 시간으로 차감하지 않습니다.

사용 시간 증액 신청에는 소속·신분·예상 총 사용 시간·선택적 수업/초대 코드·목적·희망 기간을 적습니다. 관리자는 클릭으로 승인하고 시작일부터 **6개월** 설치형 Pro를 주거나 시작·종료 날짜가 있는 학기 쿠폰을 발행합니다. Pro는 설치형에만 적용됩니다. 웹 시간·이용 자격은 별도입니다. 설치형은 계정당 하나만 실행할 수 있습니다. 오픈소스 로컬 프로그램은 변조 방지 DRM이 아니므로 로컬 파일의 점수를 공식 순위로 믿지 않습니다.

### 운영체제별 경로

| 운영체제 | 설치 방법 | GPU 지원 범위 |
|---|---|---|
| Linux | Docker Engine + 해당 CPU 구조의 런타임, 필요하면 네이티브 ROS | NVIDIA 드라이버·Container Toolkit·`--gpu`; 실제 EGL 렌더러 확인 필요 |
| Windows PC | Docker Desktop·WSL2, Ubuntu WSL 터미널에서 실행 | NVIDIA/WSL2 전달 경로 사용; 그래픽·센서 실제 검증 필요 |
| Apple Silicon Mac | Docker Desktop ARM64 + Python 3.10 이상 | 현재 Gazebo 컨테이너는 CPU 렌더링. Apple GPU 직접 전달 불가 |
| Intel Mac | 빌드·배포된 AMD64 런타임 필요 | CPU 경로, 현재 Intel Mac 실제 시험 미완료 |

Gazebo 자체의 macOS Homebrew 설치 문서는 있지만 POSIM·ROS·외부 파도 플러그인까지 네이티브로 통합하는 것은 별도 작업입니다. 이를 완료된 Mac GPU 지원으로 표시하지 않습니다. 브라우저 접속만으로 학생 컴퓨터에 ROS가 설치되지는 않습니다.

1. 공식 배포 경로로 Docker와 Python 3.10 이상을 설치합니다. Windows는 WSL2를 활성화하고 Ubuntu 터미널을 사용합니다. Docker VM에 8GB 이상, 메모리 24GB 이상 컴퓨터라면 12GB 정도 할당을 권장합니다. 성능 시험 중 다른 무거운 빌드는 중단합니다.
2. GitHub 템플릿에서 **Use this template → Create a new repository**로 팀 저장소를 만들고 클론합니다.
3. 프로젝트에서 `python3 -m venv --system-site-packages .venv`, 활성화 후 `pip install -e .`를 실행합니다.
4. 강사가 제공하는 네이티브 CPU 구조의 런타임·웹 이미지 태그를 받습니다. 현재 ARM64 이미지는 로컬에 빌드되어 있으며 공개 AMD64/ARM64 레지스트리 배포는 아직 설정되지 않았습니다. 운영자가 상위 저장소를 빌드해 제공할 때 외부 GPL 의존성의 소스·라이선스도 유지해야 합니다. ARM 에뮬레이션으로 x86 GPU 서버 성능을 평가하지 마세요.
5. 설치형을 실행합니다.

```bash
www-posim --server https://YOUR_SERVER/api --email YOU@example.edu \
  --runtime-image INSTRUCTOR_NATIVE_RUNTIME --web-image INSTRUCTOR_WEB_IMAGE
# 검증된 Linux/Windows NVIDIA 환경:
www-posim --server https://YOUR_SERVER/api --email YOU@example.edu \
  --runtime-image INSTRUCTOR_NATIVE_RUNTIME --web-image INSTRUCTOR_WEB_IMAGE --gpu
```

`http://127.0.0.1:3300`을 엽니다. 실행기를 켜둬야 권한이 갱신되며 Ctrl+C로 컨테이너와 권한을 종료합니다. 데이터는 `~/.www-posim/data`에 남습니다. 비밀번호를 저장하지 않고 기기 식별용 임의 ID만 저장합니다. 실행 권한은 60초, 갱신 간격은 20초입니다. 연결·갱신 실패나 시간 만료 시 로컬 실행이 중단됩니다. 유휴·지형 준비에는 권한을 시작하지 않지만 네이티브 월드 시작·카메라 준비는 설치형 사용 시간에 포함됩니다.

최초 다운로드에는 ROS·Gazebo·GIS·SITL 때문에 큰 이미지가 필요합니다. 이후 의존성 레이어를 재사용하고 작은 Python·웹 레이어만 갱신하도록 구성합니다. 시작 전과 5분마다 버전·프로토콜을 확인하며 최소 버전 불일치 시 새 실행 전에 업데이트해야 합니다. 임의 URL에서 프로그램을 내려받아 실행하지 않습니다. 서명된 데스크톱 설치 파일·앱스토어 배포·오프라인 라이선스까지 완료됐다고 주장하지 않습니다.

### 네이티브 ROS 없이 실습 터미널 실행

세 운영체제 모두 로컬 ROS 클라이언트 컨테이너에서 코드를 실행할 수 있습니다. 서버에 임의 패키지를 설치하는 대신 학생의 컴퓨터에서 필요한 ROS 패키지를 추가하세요.

```bash
docker run --rm -it --cpus 1 --memory 1g \
  -e ROS_DOMAIN_ID=73 -e ROS_AUTOMATIC_DISCOVERY_RANGE=LOCALHOST \
  -v "$PWD:/student" -w /student --entrypoint bash INSTRUCTOR_NATIVE_RUNTIME
source /opt/ros/lyrical/setup.bash
python3 -m venv --system-site-packages /tmp/student-env
. /tmp/student-env/bin/activate
pip install -e .
```

Linux에서 호스트의 서버/터널에 접속할 때는 `--add-host host.docker.internal:host-gateway`를 추가합니다. 컨테이너 안에서 호스트 설치형은 `http://host.docker.internal:3300/api`, 원격 서버는 실제 HTTPS 주소를 사용합니다. 컨테이너의 `127.0.0.1`은 호스트가 아닙니다. 두 번째 터미널은 `docker exec -it CONTAINER_ID bash`로 **같은 클라이언트 컨테이너**에 들어가 ROS·가상 환경을 다시 활성화합니다. LOCALHOST 탐색으로 독립 컨테이너 두 개가 저절로 연결되지는 않습니다.

## 실습 A — 센서·좌표·안전 명령

WAM-V ROS2 직접 제어 월드를 실행하고 프로필을 내려받아 릴레이를 시작합니다.

```bash
export ROS_DOMAIN_ID=73
export ROS_AUTOMATIC_DISCOVERY_RANGE=LOCALHOST
www-posim-connect --server https://YOUR_SERVER/api --email YOU@example.edu --control
# 같은 ROS 환경의 다른 터미널:
ros2 topic list -t
ros2 topic echo /model/wamv/odometry --once
ros2 topic echo /model/wamv/scan --once
ros2 topic hz /model/wamv/scan
```

세계 좌표는 +X 동쪽, +Y 북쪽, +Z 위쪽입니다. yaw 0은 동쪽을 향합니다. 나침반 표시는 이와 별도로 변환합니다. 명령의 프레임은 `base_link`, X 전진, Z 양의 회전은 위에서 볼 때 반시계 방향입니다. WAM-V 제한은 전후 ±1.5m/s, 회전 ±0.5rad/s입니다. 측면·수직 속도는 받지 않습니다.

```bash
ros2 topic pub -r 10 /wwos/cmd_vel geometry_msgs/msg/TwistStamped \
  '{header: {frame_id: base_link}, twist: {linear: {x: 0.25}, angular: {z: 0.0}}}'
```

장애물 없는 연습 월드에서 짧게 이동하고 Ctrl+C를 누릅니다. watchdog 이후 추력이 0이 되는지 확인하고 실제 관성 이동과 구분합니다. 명령이 발행됐다는 로그만으로 로봇이 제대로 움직였다고 판단하지 않습니다. 채점 월드에서는 채점을 먼저 시작하세요.

## 실습 B — 웹 서버 로봇을 로컬 코드로 제어

브라우저에서 WAM-V·ROS2 직접 제어·두 부표 연습을 선택하고 센서가 준비될 때까지 기다립니다. 로컬 ROS 터미널에서 연결하고 다른 터미널에서 예제를 실행합니다.

```bash
www-posim-connect --server https://YOUR_SERVER/api --email YOU@example.edu --control
# 같은 클라이언트 컨테이너 또는 ROS 도메인의 터미널:
www-posim-surface --distance 38 --speed 0.8
```

`receive_pose`는 실제 Odometry를 저장합니다. `receive_scan`은 센서 설치 위치 `(0,0,2.5)`와 측정 자세를 이용해 광선을 세계 좌표로 변환합니다. 간단한 높이 필터로 수면 반사를 제외합니다. 실무용 해양 탐지기 수준은 아닙니다. 지도 장애물을 4m 팽창시켜 선체 여유를 확보하고, A* 경로와 10Hz 속도·회전 명령으로 회피합니다. 예제는 장애물의 정답 좌표를 받거나 로봇 pose를 직접 바꾸지 않습니다.

릴레이를 끊었다 연결해 보고 브라우저 Stop/Enable을 시험하세요. 기본 예제의 왕복 목표는 대회 전체 해답이 아닙니다. `profile.json`의 공개 mission targets를 읽도록 확장하고, 방향·연속 유지·게이트 순서·복귀 상태 머신을 구현해야 합니다. 월드를 다시 시작하면 프로필과 세션 식별자를 다시 받아야 합니다.

인터넷 연결은 이메일 쿠키 인증과 HTTPS/WSS를 사용합니다. SSH는 기존 관리용 계정이 있는 사설 서버에서 선택적으로 쓸 수 있습니다.

```bash
ssh -N -L 19090:127.0.0.1:3000 YOUR_EXISTING_SSH_ACCOUNT@SERVER
# API http://127.0.0.1:19090/api
# WebSocket ws://127.0.0.1:19090/ros
```

이때 릴레이 Origin은 서버가 허용한 Origin과 같아야 합니다. 앱이 학생별 SSH 계정·ngrok·사용자 서브도메인·Kubernetes 터널을 생성하지는 않습니다. 일반 TLS·DNS·리버스 프록시로 배포하고 쿠키 소유권에 따라 사용자별 네이티브 슬롯으로 라우팅합니다.

## 실습 C — 설치형 로봇 제어와 수중 추력

설치형 실행기를 켜고 지형·직접 제어 월드를 생성합니다. 중앙 서버 계정은 실행기가 확인하며 로컬 월드에는 복사하지 않습니다. 로컬 게이트웨이에서는 별도 beta 로그인이 꺼져 있습니다.

```bash
curl http://127.0.0.1:3300/api/rviz/profile -o profile.json
python3 -m www_posim_autonomy.relay --url ws://127.0.0.1:3300/ros \
  --profile profile.json --control
# 클라이언트 컨테이너에서는 127.0.0.1 대신 host.docker.internal
# 다른 터미널:
www-posim-underwater --depth 2
```

추력 명령은 `std_msgs/msg/Float64MultiArray`, `/wwos/thrusters` 토픽입니다. WAM-V는 2개(각 ±200N), BlueROV2는 1~6번 순서로 6개(각 ±50N)이며 수중 템플릿은 ±20N으로 더 작게 제한합니다. 기본 수중 모델의 관절 축은 로컬 −Z입니다. 수평 전진 부호는 `[-,-,+,+]`, yaw 회전은 `[-,+,+,-]`, 두 수직 축은 아래를 향하므로 위로 올리는 힘은 음의 수직 추력입니다. SDF의 설치 방향을 바꾸면 배분 행렬도 다시 계산해야 합니다.

수중 예제는 간단한 수심 PD 제어기를 사용해 45초 시뮬레이션 시간 동안 수심을 유지한 뒤 부상을 요청합니다. 완성된 6자유도 제어기·슬라롬 해답이 아닙니다. 임무 단계는 수신한 ROS Odometry의 시뮬레이션 시각을 따르며 가속 실행에도 적용됩니다. 통신 유효성은 실제 시간으로 검사합니다. 수심 감쇠에는 기체 기준 속도를 ENU의 수직 속도로 변환해 사용합니다. 센서 데이터가 0.5초 이상 오래되면 중립 명령을 보냅니다.

```bash
ros2 topic echo /model/bluerov2/odometry
ros2 bag record /model/bluerov2/odometry /model/bluerov2/imu /wwos/thrusters
```

로컬 디스플레이가 있는 ROS 환경에서는 RViz2로 위치·TF·경로를 표시합니다. 기본 원격 프로필은 Odometry·IMU·TF와 WAM-V 라이다를 제공합니다. 수중 소나·음향 pinger를 제공한다고 가정하지 않습니다. 실제 JPEG 카메라는 브라우저/API와 프로필의 `sensor_msgs/msg/CompressedImage` 토픽으로 제공합니다. `/model/bluerov2/camera/compressed`, `/model/bluerov2/inspection/image/compressed`, `/model/wamv/camera/compressed`를 RViz의 압축 Image 표시나 OpenCV에서 구독하세요. 최대 시뮬레이션 시간 1Hz이며 구독할 때 활성화합니다. 수중 조사 영상은 문서화한 RGBD 수중 셰이더를 적용합니다. RAW Image·PointCloud2·소나는 추가 검토한 센서 프로필이 필요합니다. 로봇의 질량·관성·메시·ArduPilot 파라미터는 별도 업로드/편집 기능으로 실험할 수 있지만 공식 기본 기체 평가에는 수정 모델을 사용하지 않습니다.

## 공식 평가 조건

공식 평가는 부산 예제에서 **35.07446 N / 129.08468 E**의 수면으로 시작하며 고정 지형, 10ms 물리 간격, 목표 1배속을 사용합니다. 다른 지역·배속 실험은 연습 모드에서 합니다. 공식 파도나 물리 설정이 바뀌면 채점 시작을 거부하고, 채점 중에는 환경을 바꿀 수 없습니다. 새 시도는 월드를 다시 시작합니다. `maritime-class-2`는 보수적 3.5m WAM-V 선체와 2m 안전 보너스가 양립하도록 수상 게이트 폭을 13m로 정했습니다. 수중 게이트는 10m입니다. 이전 개발 기록은 이전 규칙 버전으로 분리합니다.

## 부문별 세 과제

공통 조건은 기본 6m/s 바람, 코스별 ±0.5m/s 풍속 변화, 110~160° 바람 방향, 경로 길이 ±10%, 측면 위치 ±3m 변화입니다. 실제 구현한 변화만 평가합니다. 랜덤 해류·센서 누락 주입·움직이는 부표·음향 센서를 구현했다고 가정하지 않습니다.

| 부문·과제 | 목표 | 구성·제한 시간 | 참고한 실제 유형 |
|---|---|---|---|
| 수상 1 | 지정 위치·방향에 도달하고 30초 유지 | 약 12m 목표, 120초 | VRX Stationkeeping |
| 수상 2 | 게이트 세 쌍을 순서대로 통과하고 복귀 | 빨강·초록 부표 쌍, 약 12/26/40m, 240초 | RobotX 채널·VRX Wayfinding |
| 수상 3 | 장애물 네 개를 피하고 시작 정박점에서 10초 유지 | 좌우 번갈아 경로, 300초 | RobotX Follow the Path·단순화한 정박 |
| 수중 1 | 2m 잠항, 게이트 통과 후 15초 유지 | 수중 기둥 두 개와 목표점, 180초 | RoboSub 게이트 |
| 수중 2 | 수심 3m 검사 경로를 따르고 복귀 | 해저 주황 표식 세 개, 240초 | RoboSub 경로 표식·WUURC 파이프라인 검사 |
| 수중 3 | 수심 2m 슬라롬, 입구 게이트로 복귀한 후 부상 | 수중 기둥 세 개·게이트·부상 목표, 300초 | RoboSub Avoid Debris·Return Home |

파이프라인 검사는 주황 표식 경로를 단순화한 것이며 손상된 배관·소나 분류가 아닙니다. 정박은 위치 유지이며 scan-code 판독·실제 접안 전체를 구현하지 않습니다. RoboSub는 경로 표식 추종 자체에 점수를 주지 않습니다. **본 수업이 별도의 경로 점수를 추가합니다.** 게이트 폭과 아래 배점도 교육용 설계입니다. 참고 대회의 전체 규칙과 동일하다고 표시하지 않습니다.

## 채점과 만점의 의미

각 과제는 100점입니다. 순서대로 도달한 목표 비율을 `c`, 위치/횡방향 RMS를 `ep`, 방향 RMS(rad)를 `eh`, 수심 RMS(m)를 `ed`, 소요 시뮬레이션 시간을 `t`, 제한을 `T`, 이상적 완료 시간을 `I`로 둡니다.

```
완료 = 60 c
정밀 = 20 c exp(-max(0,ep-0.15)/2
               -max(0,eh-5π/180)/0.5
               -max(0,ed-0.05)/0.5)
속도 = 10 c clamp((T-t)/(T-I), 0, 1)
안전 = 10 c clamp(최소 선체 여유거리/2, 0, 1)
점수 = clamp(완료+정밀+속도+안전-15×접촉 장애물 수, 0, 100)
```

장애물이 없으면 안전 점수는 `10c`입니다. 충돌은 보수적인 WAM-V 반경 3.5m, BlueROV2 반경 0.5m 선체 포락선과 기둥의 수직 겹침으로 검사합니다. **Gazebo 접촉력 적분이 아닌 명시된 기하 근사**이며 정확한 메시 접촉 전에도 가까운 통과를 벌점 처리할 수 있습니다. 장애물 하나는 한 번만 세고, 충돌이 있으면 최종 점수를 최대 50으로 제한합니다. 지형·해저 안전 및 비정상 이동 감시는 별도로 중단·무효화할 수 있지만 접촉력 점수를 만들어내지는 않습니다.

도달 판정은 수평 수상 2m/수중 1m, 수심 0.5m이며 유지 목표에는 방향 0.35rad 조건을 추가합니다. 유지 시간은 연속이어야 하며 벗어나면 초기화됩니다. 게이트 과제는 지정 목표를 순서대로 도달하는 단순 판정이며 별도의 gate-plane 통과 검출기까지 구현하지는 않았습니다. 경로 정밀도는 현재 선분까지의 횡방향 오차, 정박은 위치 오차입니다. 위치 유지 과제는 목표 영역에 처음 들어온 뒤 정밀도를 적분해 접근 거리를 정박 오차로 잘못 벌점 처리하지 않습니다.

만점 정밀도는 RMS 위치 0.15m, 방향 5°, 수심 0.05m 이하입니다. 도달 조건보다 엄격하지만 0 오차를 요구하지는 않습니다. 이상적 완료 시간은 수상 과제 50/150/210초, 수중 과제 100/170/220초입니다. 그 시간 안에 완료하고 모든 정밀도·안전 조건을 만족하면 100점이 가능합니다. 여러 거친 파도·코스에서 같은 성능을 내는 것이 어려운 부분입니다. 실제 모델·센서 한계 때문에 기준이 불가능하면 규칙 버전을 바꾸고 기준선을 다시 측정해야 하며 임의로 점수를 표시하지 않습니다.

위치가 갑자기 바뀌거나 시간이 역행·단절되거나 데이터가 유한하지 않거나 세션/소유권이 바뀌면 무효입니다. 정상적인 제한 시간 종료는 그때까지의 부분 점수를 제공합니다. RMS는 브라우저 폴링 횟수가 아니라 네이티브 시뮬레이션 시간으로 적분합니다.

## 순위표 참가 방법

1. 이메일 가입·인증 후 로컬에서 연습하세요. 연습 코스 번호 0~4를 사용할 수 있습니다.
2. 웹 월드에서 ROS2 제어·과제·**공식 평가**를 선택합니다. 공식 코스는 서버가 규칙 버전·과제·회차로 지정하며 모든 참가자가 같은 회차 조건을 사용합니다. 사용자가 임의로 쉬운 seed를 보내도 공식 선택에 반영하지 않습니다.
3. 공개 별명을 적고 **채점 시작**을 누른 뒤 ROS 명령을 보냅니다. 이메일은 공개 순위에 표시하지 않습니다.
4. 과제마다 서로 다른 코스 5개를 실행합니다. 과제 점수는 `평균 80% + 최저 20%`, 부문 점수는 세 과제 점수의 평균입니다. 5개 이전에는 임시 기록과 횟수를 표시합니다.
5. 로그인 페이지와 메인 화면의 순위표 버튼에서 설명·교재·템플릿 링크와 결과를 확인합니다.

현재 코스별 마지막 유효 기록이 이전 기록을 대체합니다. 5회 완료 후 기본 재시험은 첫 코스로 돌아가므로 결선·새 평가 묶음은 운영자가 새 규칙 버전/회차로 관리해야 합니다. 서버는 네이티브 궤적·조건·점수를 저장하지만 학생의 AI 사용 여부·직접 작성 여부나 실제 항법 추정기를 사용했다는 사실까지 증명하지는 않습니다. 시뮬레이션 정답 Odometry는 현재 항법에 허용하며 이를 보고서에 밝힙니다. 장애물 학습에는 실제 라이다·카메라를 사용하세요. 정답 좌표를 숨기는 별도 인지 전용 평가가 필요하면 센서·API 접근 규칙을 새로 정의해야 합니다.

ArduPilot 기본 파라미터 기록은 항상 고정 기준선으로 표시합니다. 새 Autopilot 월드에서 포함된 기본 기체 설정과 시뮬레이터 항법 연결을 사용하고 파라미터를 수정하지 않은 상태로 같은 경로를 실행합니다. 실제 하드웨어의 완전한 출고 EEPROM 설정이라는 뜻은 아닙니다. 수상 avoidance 기능을 켜거나 파라미터를 바꾸면 다른 비교군입니다. Rover는 BendyRuler 등 설정된 장애물 회피를 지원하지만 기본값만으로 의미 있는 부표 인식·수중 소나·회피를 한다고 가정하지 않습니다. 상위 지형 우회 플래너와 라이다 장애물 회피도 다릅니다.

측정 전 점수는 “측정 전”이며 임의의 0/100을 넣지 않습니다. 실제 seed 하나의 기준선은 임시 기록이지 5회 확정 순위가 아닙니다. 설치형은 코드·로그를 수정할 수 있으므로 연습 점수로만 취급하고 공식 순위는 서버 측정으로 제한합니다.

- 반대로 잠항하면 관절 축·선체 변환·힘 부호를 다시 계산하고 작은 추력 펄스로 시험합니다.
- 카메라에 하늘만 나오면 수중 검사 카메라·pose·far 범위를 확인합니다. 브라우저의 장식 수면은 센서 검증이 아닙니다.
- 점수가 낮으면 순서·연속 유지·횡방향/방향/수심 오차·보수적 선체 여유를 네이티브 보고서로 확인합니다.
- 서버가 바쁘면 잔여 시간 확인·재접속·로컬 연습을 선택합니다. Pro는 웹 슬롯 예약이 아닙니다.
- 이메일이 안 오면 SMTP 설정 문제입니다. 도메인을 적는 행위를 인증으로 대신하지 않습니다.
- GPU가 안 쓰이면 실제 렌더러를 확인합니다. CPU 물리, 렌더러, 센서 변환, 메모리를 나눠 측정하고 하드웨어를 구매합니다.
